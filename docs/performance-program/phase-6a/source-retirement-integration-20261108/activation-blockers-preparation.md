## Force POST review assertions

In the prepared actual `loadFromServer`, the first action is capture of source/session intent. If current Orders is thin, it awaits the real `ensureOrdersFullForAction('orders.refresh.start')`, whose real private controller must publish full and provide a validated receipt. Only then may it execute syncLinkedRefreshMembers, linked-target expansion, commitOpenCellEditors, settleOverrideWrites, timers, or the existing `fetch('/api/refresh',{method:'POST',...})`. Failure returns false through localized status/toast; it cannot fall through into that POST. The original function still contains one refresh POST dispatch; no helper adds another POST. The proposed native ordering test uses the real helper and real loadFromServer, suspends native controller publication, asserts zero linked/editor/settle/fetch actions before resolving, then records the one POST. A separate rejection test asserts zero actions after failed promotion. These tests are prepared, not run or counted as evidence.

`ensureOrdersFullForAction` returns ordinary full rows without an await/fetch/controller inside its full branch. The caller only inserts a preflight await for a current thin source. Existing full-force preflight retains its original linked-source/write-settlement waits. Cancellation is client request/subscriber cancellation only; no backend CPU cancellation is claimed.
