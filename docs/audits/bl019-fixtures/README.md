# Isolated Windows desktop acceptance

These fixtures require Windows, an existing compatible Electron runtime, Playwright's Electron driver, and installed application dependencies. They generate synthetic orders and IAM profiles. They do not connect to ASAS, publish updates or use the user's data. OS shortcut/icon changes and external mail opening are suppressed; production main, watchdog, backend, workspace, preload and renderer remain in use. The signed launcher boundary has separate acceptance evidence.

1. Run `node prepare-runtime.cjs <installed-executable>` to copy runtime files into a new temporary directory. The original resources and data are excluded. Record the returned executable and digest.
2. Set `BUYER_LOG_ELECTRON_EXECUTABLE` to that returned executable. Set `BUYER_LOG_PLAYWRIGHT_MODULE` to the installed Playwright module path when it is outside normal Node resolution.
3. Run `node boot-samples.cjs`. The printed evidence directory receives raw samples. Five fresh synthetic data roots are followed by twenty persisted-data process restarts. OS caches are not purged. Shell readiness, explicit continue and populated Overview readiness are separate metrics. The first persisted run also performs twenty distinct order searches.
4. For interactive export acceptance, use the generated isolated data root and the same test main. Export CP with all rows, cancel a separate export, and export Collection with images. Expected values are 30,030 physical CP lines / 30,000 unique orders, and 300 Collection model rows / 30 unique image payloads. There are 300 owner workspace files; ten contain 300 models each and 290 contain one model. This is explicitly different from 300 full workspaces.
5. `office-acceptance.ps1 -FixtureRoot <isolated-root>` expects `collection-with-images.xlsx` and `cp-30030-current.xlsx`. It opens workbooks read-only and roundtrips a recipient-free synthetic local MSG without Send or mailbox Save. It does not quit an existing Outlook application. In the recorded environment, both Office COM factories failed with `0x80080005`; no native Office success is claimed.

The recorded live interaction driver also checked current scoped reads and durable workspace writes through ten separate authenticated sessions, target-price and note persistence after restart, keyboard navigation and native 200% TR/EN layouts. Those results are in the sibling BL019 evidence JSON. A local shared-folder simulation is not actual SMB/OneDrive acceptance. A real supported UNC root and working Office installation are external acceptance requirements.
