# Explicit output-schema migration gaps

Current executable catalog audit: 180 contract-v2 tools; 180 declare a strict top-level output object; 0 still use a generic verified envelope or an open top-level result. The currently registered adapters now declare strict result contracts backed by their native regression cases. This closes the known top-level migration inventory; it does not prove every native user action is registered or provide release acceptance.

| Module | Open output contracts | Registered tool IDs |
|---|---|---|

New adapter groups must declare their real native result and inverse receipt. Dynamic canonical records and analytical columns need a bounded typed value/dictionary or row/cell contract, with declared omissions. Before changing a write result schema, verify the actual native effect/receipt so a valid persisted effect does not become a false failed task because of a newly invented response shape. Preserve the existing engine, IAM, record scope, audit and approval boundary. Validate groups with their actual capability/native regression cases and one focused review; do not combine independent risky adapters into one delivery PR.
