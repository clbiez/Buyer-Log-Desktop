# Native reusable checklist decisions

Two Office tools adapt the existing checklist supplier store: `cp.checklist.options.read` and approved `cp.checklist.options.update`. Only explicitly authorized CP order keys are accepted. Native CP analysis and optionIdentity derive the PLM/model/colour key; raw option IDs, missing/ambiguous identities, duplicate decisions and keys exceeding the native 300-character limit fail before effects. The preview declares existing/future option reuse without claiming access to other owners' records or an impact count.

The actual current personal/inherited rule snapshot is merged through Rules.mergeWithDefaults. UPDATE requires an effective native checklist question with option approval scope. Legacy shared definitions require the native one-time adoption to become effective; the adapter does not silently adopt definitions or change question scope. Native default order questions, deletions and personal order overrides are rejected before approval or writing. Only Approved is reused by the native engine; Pending/Open revokes global approval. PO-specific answers win and are preserved.

The native file lease, safe revision headroom (two forward/one inverse), current IAM/source authority and actual Office profile WAL guard protect changes. Complete prior answers/tombstones and legacy metadata are archived by the existing framed owner/tool/task/step-bound inverse service. Evidence is preserved and omitted from public payloads. Inverse refuses newer native revisions or changed anchor identities. The native committed receipt is retained privately before any public authorization recheck. READ pages have a 64KB budget, preserve identities and require an unchanged fingerprint for continuation.

Focused review found a real scope mismatch: the former implementation could complete an option write for the native default order-only tests question while native CP remained Open. The unchanged reproduction now rejects with OFFICE_TASK_INVALID and writes zero answers; the focused closure reports no open P0/P1. Positive tests derive native itemScopes from real normalized option rules; no forced renderer scope is used.

Forty-four targeted capability/shared-answer/matrix tests pass with zero failures or skips and cover approval, actual native reusable status and future matching orders, negative scopes, source/agent/IAM changes, evidence/legacy inverse, peer writes, task-bound artifact and archive failure, UTF-8 paging, native final safe revisions and actual Office service reconstruction without another write. The adjacent main packet already ran complete regression; final release still requires its own full platform regression.

Actual anonymous HTTP/Chromium acceptance uses an isolated native persisted DEMO source snapshot with a complete PLM identity and creates the real option rule via existing cp.rule.save. It approves the option, reads the native receipt, restores exact answers/tombstones and inverses the personal rule. Both UI languages and zero page errors were verified; a real 1440×960 post-change PNG is included. This is local native acceptance, not corporate provider/PLM/LCW AI/physical Windows acceptance.
