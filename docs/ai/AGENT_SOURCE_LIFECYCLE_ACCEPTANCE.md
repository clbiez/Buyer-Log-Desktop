## Connection CREATE / DELETE (2026-10-14)

`source.connection.create` and `source.connection.delete` extend the same native source workflow service (model-connection lease, store/source revision CAS, read-back). CREATE accepts only a name, a manually creatable profile, optional feedable modules and `targetSourceId`; the server/model are copied from that already configured source inside the lease and are never accepted from the caller or shown in previews/receipts. The native `planSourceCreate` rules apply (limit, feedable modules, duplicate-target and one-active-role warnings: a second source of an active role is created disabled). Its inverse removes only the created source while its source revision is unchanged.

DELETE uses native `planSourceDelete` (optional name confirmation and required-module protection: ASAS/IAS/INTAKE sources that feed required modules cannot be deleted, same as the HTTP route). Sources with a stored credential are refused, because a credential cannot be restored by an inverse. The complete configuration and its position are archived privately (owner/task/step bound); the inverse reinserts it exactly and refuses an id clash, a peer that activated the same role, or a full source list (native normalization keeps only 20 entries, so a restore must never push a peer out); every prior id is verified after the write. Native Turkish planner warnings carry an English translation in Office receipts.

Validation: 5 new live cases (approval, hidden target, schema rejection of host/model/SQL/credential, non-manual profile, stale preview, edited-source inverse refusal, required/credential/name protection, exact positional restore, id clash, IAM loss) plus 35 source/data-management/matrix files pass. Actual anonymous HTTP/Chromium: 409 without approval, completed create (disabled duplicate with bilingual native warnings), completed custom-source delete, and both inverses through the real Office undo dialog restored the prior source list; TR/EN, zero page errors. No corporate connection is claimed.

## Saved configured query READ / EXPORT (2026-10-14)

`source.query.read` (READ) and `source.query.export` (EXPORT, approval, existing native report output service) run only the query already saved on a configured database source (`role: custom` with a connector), through the same providers as `/api/database-sources/:id/query` and the stored credential; the caller cannot pass query text. Source revision and live/agent authority are rechecked before and after the provider call, so a source edited during the run returns `SOURCE_CHANGED` instead of mixed data. Cells are scalar and bounded (500 characters, 40 columns, 1–1000 rows, 64KB pages); provider error text is not echoed. EXPORT re-runs the query at apply and refuses a changed or truncated result.

The Office HTTP error filter previously mapped the newer native source codes (including those of the create/delete tools) to `OFFICE_INTERNAL`/500; they are now passed through and have TR/EN UI explanations.

Validation: 4 new cases with an injected provider (bounded rows, no SQL input, unsupported source, IAM, revision change, provider-error redaction, approval-gated single export, changed-result refusal, route/UI code contract). Actual anonymous HTTP/Chromium: both tools appear for a source agent (READ without approval, EXPORT with approval), a non-database source returns `SOURCE_QUERY_UNAVAILABLE` through HTTP, and the real operation dialog lists the export tool; TR/EN, zero page errors. No real database/Analysis Services provider ran in this Linux environment; provider execution remains corporate/Windows acceptance.
